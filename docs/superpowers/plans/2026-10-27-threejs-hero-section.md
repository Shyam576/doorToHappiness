# Three.js Hero Section Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the homepage's 3-image photo crossfade hero with a stylized, procedurally-built low-poly 3D Tiger's Nest scene, with a static-image fallback for reduced-motion/no-WebGL/save-data users.

**Architecture:** A self-contained `src/components/hero3d/` module exposes `Hero3DOverlay`, a client-only (no-SSR) layer that sits on top of a plain, server-rendered `<Image>` in `src/pages/index.tsx`. The static image is always present (preserves LCP/SEO); `Hero3DOverlay` mounts a `@react-three/fiber` canvas only when support checks pass, and crossfades it in once ready. Any 3D render failure is caught by an error boundary and silently falls back to the static image.

**Tech Stack:** Next.js 13 (pages router), React 18, TypeScript, `three`, `@react-three/fiber`, Jest + Testing Library (existing). (`@react-three/drei` was evaluated for the ambient mist effect but dropped — see the amendment note below.)

**Spec:** `docs/superpowers/specs/2026-10-27-threejs-hero-design.md`

## Global Constraints

- 3D scene fully replaces the photo crossfade (not a background layer, not a small object) — per spec.
- Model is a stylized, low-poly Tiger's Nest built procedurally in code — no external 3D modeling tool, no licensed/photoreal asset.
- Interactivity: ambient animation + mouse/scroll-reactive camera only — no drag-to-orbit.
- Fallback is a full static-image replacement (not a degraded 3D scene) for: `prefers-reduced-motion: reduce`, no WebGL, or `navigator.connection.saveData`.
- Integration via `@react-three/fiber`, loaded with Next `dynamic(..., { ssr: false })`. (The spec also approved `@react-three/drei` as an available helper library; Task 5's original mist effect used drei's `Cloud`, but that was found to violate the "no textures" constraint below and was replaced — see the amendment note.)
- `dpr` capped at `[1, 1.5]`; no textures; low-poly primitives only; reactive state lives in refs read inside `useFrame`, never triggers React re-renders.
- `<canvas>` gets `aria-hidden="true"` and `tabIndex={-1}`; static fallback keeps its existing meaningful `alt` text.
- The actual WebGL scene (`HeroCanvas`/`TigersNestModel`/`useReactiveCamera`) is not unit-tested (jsdom has no WebGL) — verified manually in a real browser instead. Only the fallback-decision logic and the overlay's support-gating are unit-tested.
- Package manager is `pnpm` (see `pnpm-lock.yaml`).

**Note on file boundaries vs. the spec:** The spec described one `TigersNestHero.tsx` component owning both the static image and the 3D layer. This plan splits that in two for SSR correctness: the static `<Image>` stays directly in `index.tsx` (always server-rendered, so it remains the true LCP element), and everything that touches `three`/`@react-three/fiber` lives in `Hero3DOverlay.tsx`, which is the piece loaded with `ssr: false`. If the static image were inside the `ssr:false` component, it would disappear from server-rendered HTML entirely, defeating the spec's LCP/SEO goal. All decisions (what renders, when, and why) are unchanged from the spec — only which file they live in.

**Amendment (found during Task 5's review, after Tasks 1 and 5 were already committed):** Task 5's original code used `@react-three/drei`'s `Cloud` component for ambient mist. Reading drei's actual implementation (`node_modules/@react-three/drei/core/Cloud.cjs.js`) showed it defaults to fetching a texture from a hardcoded third-party CDN URL (`https://rawcdn.githack.com/pmndrs/drei-assets/...cloud.png`) via `useTexture`, and renders it as a textured instanced sprite. This directly violates this plan's own "no textures" constraint (line above) and adds an external network dependency for a purely decorative hero element — a reliability and scope problem the spec's "self-contained, built procedurally in code" philosophy was specifically meant to avoid. Since `Cloud` was the only use of `@react-three/drei` anywhere in this plan (confirmed by search), dropping it leaves the dependency with no remaining justification, so it is removed entirely rather than kept unused. Task 5's mist effect is replaced with plain, texture-free `@react-three/fiber` primitives (flat semi-transparent planes, gently animated via `useFrame` — see Task 5's updated code). Task 1's dependency list and install command are updated to drop `@react-three/drei`. This does not reverse the spec's approved integration decision (`@react-three/fiber`, declarative JSX, not vanilla three.js in a `useEffect`) — it only drops one specific, no-longer-usable helper library.

```ts
interface NetworkInformationLike {
  saveData?: boolean
}

export function detectHero3DSupport(): boolean {
  if (typeof window === 'undefined') {
    return false
  }

  if (typeof window.matchMedia === 'function' && window.matchMedia('(prefers-reduced-motion: reduce)').matches) {
    return false
  }

  const connection = (navigator as Navigator & { connection?: NetworkInformationLike }).connection
  if (connection?.saveData) {
    return false
  }

  try {
    const canvas = document.createElement('canvas')
    const gl = canvas.getContext('webgl') || canvas.getContext('experimental-webgl')
    if (!gl) {
      return false
    }
  } catch {
    return false
  }

  return true
}
```

### Task 4: Mouse/scroll-reactive camera rig

**Files:**
- Create: `src/components/hero3d/useReactiveCamera.ts`

**Interfaces:**
- Consumes: must be called from a component rendered inside a `<Canvas>` tree (uses `useThree`/`useFrame` from `@react-three/fiber`).
- Produces: `useReactiveCamera(): void` — side-effecting hook, no return value. Used by `HeroCanvas` (Task 5).

- [ ] **Step 1: Implement the hook**

Create `src/components/hero3d/useReactiveCamera.ts`:

```ts
import { useEffect, useRef } from 'react'
import { useFrame, useThree } from '@react-three/fiber'

const BASE_CAMERA_X = 0
const BASE_CAMERA_Y = 1.2
const MAX_SCROLL_INFLUENCE = 400

export function useReactiveCamera(): void {
  const { camera } = useThree()
  const scrollRef = useRef(0)

  useEffect(() => {
    const handleScroll = () => {
      scrollRef.current = window.scrollY
    }
    window.addEventListener('scroll', handleScroll, { passive: true })
    return () => window.removeEventListener('scroll', handleScroll)
  }, [])

  useFrame((state) => {
    const { pointer } = state
    const clampedScroll = Math.min(scrollRef.current, MAX_SCROLL_INFLUENCE)

    const targetX = BASE_CAMERA_X + pointer.x * 0.6
    const targetY = BASE_CAMERA_Y + pointer.y * 0.3 - clampedScroll * 0.0015

    camera.position.x += (targetX - camera.position.x) * 0.05
    camera.position.y += (targetY - camera.position.y) * 0.05
    camera.lookAt(0, 2, 0)
  })
}
```

**Amendment (found during the final whole-branch review, after this task had already shipped):** the code above reads `state.pointer`, which React-Three-Fiber only updates from pointer events it receives on the `<Canvas>`'s own DOM wrapper (`@react-three/fiber`'s `connect(eventSource ? ... : divRef.current)` — confirmed by reading `node_modules/@react-three/fiber/dist/react-three-fiber.esm.js`). In `index.tsx` (Task 8), the hero section's `<Container className="relative z-10 h-full ...">` is a DOM **sibling** of `Hero3DOverlay`'s wrapper, stacked above it (`z-10`) and spanning the full hero area (`w-full h-full`). A hit-test at the canvas's own center (confirmed with `document.elementFromPoint`) resolves to a CTA button inside `Container`, not the canvas — so native pointer events never reach the canvas's wrapper, and `state.pointer` never updates from its default. A controlled before/after screenshot comparison (no mouse input vs. mouse movement, sampled pixel bytes) showed statistically indistinguishable diffs (12654 baseline vs. 12613 after movement) — mouse movement has zero measurable effect on the rendered scene. The "mouse-reactive camera" requirement was therefore inert on the deployed page despite passing Task 4's own review and an earlier (confounded) manual-QA check in Task 9 — that check's before/after canvas screenshot diff couldn't distinguish real camera movement from `MistPatch`'s constant per-frame opacity animation, which changes canvas pixels regardless of input.

Fix: stop relying on R3F's `state.pointer` (DOM-stacking-dependent) and track the pointer directly via a `window`-level `pointermove` listener into a ref, mirroring the already-working `scroll` listener pattern in this same hook — `window`-level listeners aren't affected by which element is topmost in the paint order. Restricted to `event.pointerType === 'mouse'` so a mobile touch-drag used for scrolling the page doesn't also swing the camera. `scrollRef`'s initial value is also changed from a hardcoded `0` to `window.scrollY`, so a visitor who lands already scrolled (e.g. via an anchor link or browser scroll restoration) doesn't get an incorrect initial camera offset until the next scroll event — a separate, previously-deferred Task 4 minor finding, bundled into this same fix since it's the same file and same pass. Replace the entire file with:

```ts
import { useEffect, useRef } from 'react'
import { useFrame, useThree } from '@react-three/fiber'

const BASE_CAMERA_X = 0
const BASE_CAMERA_Y = 1.2
const MAX_SCROLL_INFLUENCE = 400

export function useReactiveCamera(): void {
  const { camera } = useThree()
  const scrollRef = useRef(window.scrollY)
  const pointerRef = useRef({ x: 0, y: 0 })

  useEffect(() => {
    const handleScroll = () => {
      scrollRef.current = window.scrollY
    }
    const handlePointerMove = (event: PointerEvent) => {
      if (event.pointerType !== 'mouse') return
      pointerRef.current = {
        x: (event.clientX / window.innerWidth) * 2 - 1,
        y: -((event.clientY / window.innerHeight) * 2 - 1),
      }
    }
    window.addEventListener('scroll', handleScroll, { passive: true })
    window.addEventListener('pointermove', handlePointerMove, { passive: true })
    return () => {
      window.removeEventListener('scroll', handleScroll)
      window.removeEventListener('pointermove', handlePointerMove)
    }
  }, [])

  useFrame(() => {
    const clampedScroll = Math.min(scrollRef.current, MAX_SCROLL_INFLUENCE)

    const targetX = BASE_CAMERA_X + pointerRef.current.x * 0.6
    const targetY = BASE_CAMERA_Y + pointerRef.current.y * 0.3 - clampedScroll * 0.0015

    camera.position.x += (targetX - camera.position.x) * 0.05
    camera.position.y += (targetY - camera.position.y) * 0.05
    camera.lookAt(0, 2, 0)
  })
}
```

```tsx
import { useRef } from 'react'
import { Canvas, useFrame } from '@react-three/fiber'
import * as THREE from 'three'
import { TigersNestModel } from './TigersNestModel'
import { useReactiveCamera } from './useReactiveCamera'

interface HeroCanvasProps {
  onReady: () => void
}

function CameraRig(): null {
  useReactiveCamera()
  return null
}

interface MistPatchProps {
  position: [number, number, number]
  size: [number, number]
  baseOpacity: number
  rotation?: [number, number, number]
}

function MistPatch({ position, size, baseOpacity, rotation = [0, 0, 0] }: MistPatchProps) {
  const materialRef = useRef<THREE.MeshBasicMaterial>(null)

  useFrame((state) => {
    if (materialRef.current) {
      materialRef.current.opacity = baseOpacity + Math.sin(state.clock.elapsedTime * 0.3) * 0.05
    }
  })

  return (
    <mesh position={position} rotation={rotation}>
      <planeGeometry args={size} />
      <meshBasicMaterial ref={materialRef} color="#e8eef2" transparent opacity={baseOpacity} depthWrite={false} />
    </mesh>
  )
}

export function HeroCanvas({ onReady }: HeroCanvasProps): JSX.Element {
  return (
    <Canvas
      dpr={[1, 1.5]}
      camera={{ position: [0, 1.2, 7], fov: 45 }}
      gl={{ antialias: true, alpha: true }}
      onCreated={() => onReady()}
    >
      <ambientLight intensity={0.6} />
      <directionalLight position={[5, 8, 5]} intensity={1.1} color="#ffe9c7" />
      <fog attach="fog" args={['#8fa8bf', 5, 18]} />
      <MistPatch position={[-3, 4, -4]} size={[6, 3]} baseOpacity={0.25} rotation={[0, 0.3, 0]} />
      <MistPatch position={[3, 2.5, -3]} size={[5, 2.5]} baseOpacity={0.18} rotation={[0, -0.3, 0]} />
      <TigersNestModel />
      <CameraRig />
    </Canvas>
  )
}
```

```tsx
import React from 'react'

interface HeroErrorBoundaryProps {
  children: React.ReactNode
}

interface HeroErrorBoundaryState {
  hasError: boolean
}

export class HeroErrorBoundary extends React.Component<HeroErrorBoundaryProps, HeroErrorBoundaryState> {
  state: HeroErrorBoundaryState = { hasError: false }

  static getDerivedStateFromError(): HeroErrorBoundaryState {
    return { hasError: true }
  }

  componentDidCatch(error: Error, info: React.ErrorInfo): void {
    console.error('Hero 3D scene failed to render, falling back to static image', error, info)
  }

  render(): React.ReactNode {
    if (this.state.hasError) {
      return null
    }
    return this.props.children
  }
}
```

```tsx
import { useState } from 'react'
import { useHero3DSupport } from './useHero3DSupport'
import { HeroErrorBoundary } from './HeroErrorBoundary'
import { HeroCanvas } from './HeroCanvas'

export default function Hero3DOverlay(): JSX.Element | null {
  const { supported, checked } = useHero3DSupport()
  const [canvasReady, setCanvasReady] = useState(false)

  if (!checked || !supported) {
    return null
  }

  return (
    <div
      aria-hidden="true"
      tabIndex={-1}
      className={`absolute inset-0 transition-opacity duration-1000 ease-in-out ${
        canvasReady ? 'opacity-100' : 'opacity-0'
      }`}
    >
      <HeroErrorBoundary>
        <HeroCanvas onReady={() => setCanvasReady(true)} />
      </HeroErrorBoundary>
    </div>
  )
}
```
